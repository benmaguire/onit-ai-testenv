# dc-ot-sim

A simulated **data centre OT plant** (power, cooling, water, leak detection).
Every device is served over the protocols real equipment speaks:
**Modbus TCP**, **SNMPv2c** and **DMTF Redfish**. A DCIM-style collector
polls it like a BMS/EPMS would. Use it to test DCIM/BMS integrations,
alerting, runbooks, capacity and failover logic, and how AI workloads respond
to facility events, all without touching real plant. It's standalone (no GPUs)
and runs on amd64 and arm64.

The standards behind it, and how to adapt it to a vendor's hardware or a
country, are covered in [docs/ot-standards.md](../../docs/ot-standards.md).

## What it deploys

| Resource | Details |
|---|---|
| Deployment `otsim` | The simulator ([otsim/](otsim/), Go): plant model + protocol servers + admin API. 1 replica, 50m–500m CPU / 64–256 MiB |
| ConfigMap `otsim-site` | The site: 26 devices from `siteConfig` in [values.yaml](values.yaml) (utility, ATS, 1.5 MW generator, 600 kW UPS, SunSpec meter, 400 kW CDU, 2 CRAH, chiller, leak sensor, 16 rack PDUs) |
| ConfigMap `otsim-profiles` | `extraProfiles`: your vendor maps and regions |
| Service `otsim` | `admin` 8080 (API + `/metrics`), `redfish` 8443, `modbus` 502 (gateway: unit ID = device index + 1), `snmp` 161/udp (community = device ID) |
| Service `otsim-<device>` | One per device, like separate IPs on a plant network: `modbus` 502 and/or `snmp` 161/udp (community `snmpCommunity`) |
| Deployment `dcim-collector` | Telegraf polling every device over Modbus, SNMP and Redfish (config generated by `otsim telegraf-config`), exported on `metrics` 9273 |

### Devices and protocols

| Device type | Modbus map | SNMP | Redfish | Points (examples) |
|---|---|---|---|---|
| `utility` | — | — | — | `voltage_v`, `frequency_hz`, `available` |
| `ats` | `generic-ats` | — | `PowerEquipment/TransferSwitches` | `source` (1 utility, 2 generator), `utility_available`, `generator_available` |
| `generator` | `generic-genset` | — | — | `state`, `running`, output V/Hz, `run_seconds` |
| `ups` | `generic-ups` | `ups-mib` (RFC 1628) | — | `on_battery`, `battery_charge_pct`, `battery_runtime_min`, `output_kw` |
| `power-meter` | `sunspec-203` (SunSpec model 1 + 203) | — | — | per-phase V/A/kW, energy |
| `cdu` | `generic-cdu` | — | `ThermalEquipment/CDUs` | supply/return °C, flow, ΔP, pumps, reservoir, setpoints (writable) |
| `crah` | `generic-crah` | — | — | supply/return air °C, humidity, fan kW, setpoint |
| `chiller` | `generic-chiller` | — | — | chilled water supply/return, COP, kW, ambient |
| `leak-sensor` | `generic-leak` | — | `ThermalEquipment/CDUs/<cdu>/LeakDetection` | `leak_detected` |
| `rack-pdu` | — | `entity-sensor-pdu` (ENTITY-SENSOR-MIB) | `PowerEquipment/RackPDUs` | `power_kw`, `current_a`, `breaker_closed`, inlet °C |

The plant model links these devices. Utility loss puts the UPS on battery,
then the generator starts and the ATS transfers. IT heat goes into the CDU
(liquid) and the CRAHs (air), both reject it to the chiller, and the chiller's
efficiency depends on the region's ambient. It computes PUE, WUE, water use,
carbon and ASHRAE inlet alarms, along with alarms for each device.

## Configuration

| Value | Default | What it does |
|---|---|---|
| `region` | `au` | Country profile: voltage/frequency, climate, display units, carbon, reporting rules. `au us eu de nordics uk sg in ae jp-east jp-west` |
| `siteConfig` | 400 kW AI hall | Devices, sizes (`params`), protocols per device, IT load profile, liquid fraction |
| `extraProfiles` | `{}` | Add or override `modbus/*.yaml`, `snmp/*.yaml`, `regions/*.yaml` without rebuilding |
| `snmpCommunity` | `public` | Community on the per-device SNMP Services |
| `image` | `ghcr.io/benmaguire/onit-ai-testenv/otsim:0.1.0` | Built by [.github/workflows/otsim.yaml](../../.github/workflows/otsim.yaml); `make up` builds and loads it locally |

## Lifecycle

Starts disabled: `scripts/envctl.sh up dc-ot-sim --push`, or locally `make up ENV=dc-ot-sim`.

| | What runs |
|---|---|
| `state: up` | otsim + dcim-collector |
| `state: down` | both at 0 replicas (the plant state resets on the next start) |
| `enabled: "false"` | namespace and everything in it deleted |

## Verify

```bash
kubectl -n dc-ot-sim port-forward svc/otsim 8080 8443 &
curl -s localhost:8080/api/v1/status | jq '{healthy, kpi: .kpi | {pue, it_kw, facility_kw, rack_inlet_c}}'
curl -s localhost:8443/redfish/v1/ThermalEquipment/CDUs/cdu-1/SecondaryCoolantConnectors/1 | jq '.SupplyTemperatureCelsius'

# Modbus and SNMP from inside the cluster, as a BMS would:
kubectl -n dc-ot-sim run probe --rm -it --restart=Never --image=alpine -- sh -c \
  'apk add -q net-snmp-tools && snmpget -v2c -c public otsim-ups-1 1.3.6.1.2.1.33.1.2.4.0'   # upsEstimatedChargeRemaining

# What the DCIM collector reads:
kubectl -n dc-ot-sim port-forward svc/dcim-collector 9273 &
curl -s localhost:9273/metrics | grep -E 'otsim_(modbus|snmp|redfish)_' | head
```

## Faults

Inject faults with the admin API (`POST /api/v1/faults`), or as simulations
with baselines and reports through the simulation controller (`ot-*` types,
[simulations/dc-ot-sim](../../simulations/dc-ot-sim/README.md)):

| Power | Cooling and water | Monitoring path |
|---|---|---|
| `utility-outage`, `utility-sag`, `frequency-deviation`, `generator-fail-to-start`, `ups-battery-degraded`, `ups-failure`, `pdu-breaker-trip`, `pdu-overload`, `it-load-surge` | `cdu-pump-failure`, `cdu-leak`, `leak`, `crah-failure`, `chiller-trip`, `high-ambient` | `sensor-stuck`, `sensor-drift`, `comms-loss` (modbus / snmp / redfish / all) |

```bash
curl -s -XPOST localhost:8080/api/v1/faults -d '{"type":"utility-outage","durationSeconds":120}'
curl -s -XPOST localhost:8080/api/v1/faults -d '{"type":"cdu-pump-failure","device":"cdu-1","params":{"pump":0}}'
curl -s localhost:8080/api/v1/fault-types | jq -r '.[].type'
curl -s -XDELETE localhost:8080/api/v1/faults          # clear all
```

## Observability

With [observability](../observability/README.md) running, Prometheus scrapes
`otsim` (`otsim_site{kpi=...}`, `otsim_point`, `otsim_alarm`,
`otsim_fault_active`) and `dcim-collector` (`otsim_modbus_*`, `otsim_snmp_*`,
`otsim_redfish_*`, which is what reached the collector over the wire). The
**Data centre OT (otsim)** Grafana dashboard shows PUE, the power path,
cooling and the two views side by side, and annotates faults.

## Adapting

- **Your hardware:** write a profile from the vendor's register map or MIB.
  Put it in `extraProfiles` and point the device's `protocols` at it. See
  [docs/ot-standards.md](../../docs/ot-standards.md#adapting-to-different-hardware).
- **Your country:** set `region`, or add one in `extraProfiles`. See
  [docs/ot-standards.md](../../docs/ot-standards.md#adapting-to-different-countries).
- **Your topology:** edit `siteConfig.devices` (2N UPS, more CDUs, more racks).
- **Outside Kubernetes:** `cd otsim && go run ./cmd/otsim serve --config examples/site.yaml --modbus-gateway tcp://0.0.0.0:1502 --snmp-addr :1161`.

## Limits

- The protocol subsets cover monitoring and setpoints. SNMP is v2c read-only
  (no v3, no traps). Redfish is plain HTTP without sessions or eventing.
  Modbus is TCP only (no RTU/serial).
- BACnet and OPC UA are not implemented yet.
- The physics are first-order (lumped thermal masses, simple COP curves):
  realistic enough for alarm and control-path testing, but not for design.
